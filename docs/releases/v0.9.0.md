# v0.9.0

A job's state, exit code and report now say what actually happened. Five production reports showed
the same failures again and again: a 429 arrived as a generic error, a `SUCCESS` report admitted a
build that was still running, a failed job left partial work with no list of what it touched, and a
piped `wait` hid exit 2 so a running job looked finished.

## New terminal outcomes

- **`quota_exhausted` (exit 6).** A model quota failure is its own state, with `resets_in` taken
  verbatim from AGY (`Resets in 4h1m13s`), the partial response kept, and a recovery that says to
  switch worker or model or wait for the reset. It never suggests `continue` on the same model.
  Classification reads AGY's final error. On stderr it trusts only unambiguous markers
  (`RESOURCE_EXHAUSTED`, `code 429`, `Individual quota reached`), so a retried tool 429 or a stray
  "429" in the log does not count.
- **`verification_incomplete` (attention, exit 5).** For `implement` and `staffer`, a report whose
  own text says it is still waiting on a build, a test or a suite, in English or Portuguese, is no
  longer `done`. The whole report is scanned, so a pending line at the top counts too. Quoted and
  fenced text is ignored, and a later "build passed" clears the pending line.
  `implement_no_changes` and `implement_uncommitted` keep precedence.
- **`## Partial work`.** Every report that does not end `done` lists HEAD before and after, the dirty
  paths after the run (marking untracked, staged and new files, and paths that were already dirty),
  the commits the run made, the commands to inspect them, and whether that list is complete. It
  compares git status only: a path that was already modified and changed again is marked "content
  change not tracked".

## Collection

- When `wait` expires on a running job, stderr says
  `STILL RUNNING — job <id>, <n>s elapsed. Exit 2: not delivered; call wait again.` Stdout stays
  the same JSON as before.
- `wait --until-done` blocks until the job ends, with no time limit. It cannot be combined with
  `--timeout` and works with `--follow`. It is meant for hosts that notify when a background command
  finishes (Claude Code `run_in_background`). In Codex, keep `wait --timeout 10m` and call it again.
- The header of `wait` and `result` shows a `Usage:` line with input, output, thinking and cache
  tokens, duration and turns, including for failed jobs.
- `continue` and `restart` print a warning, without blocking, when they would reuse a model that
  ran out of quota and whose reset window is still open.

## Skills

`jobs` now has one action table per state and reason. It says to never pipe `wait` and how to
collect a job in each host. The Codex permission sentence is now conditional: request escalated
permissions only when the sandbox blocks agy's localhost port or OAuth file.
