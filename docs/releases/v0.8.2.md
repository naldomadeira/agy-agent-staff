# v0.8.2

Seven fixes, all drawn from one real run: 30 tasks across two repositories, 5 PRs merged, with
every delivery verified independently. None of this is speculative — each item is a failure that
cost time that night.

## The work that exists and is never delivered

Four times, agy did the work and did not commit: correct files in the working tree, tests passing,
`HEAD` unmoved, and a report that read like success. Twelve and six files came within one cleanup
of being deleted.

That was not a defect. It is the contract `templates/implement.md` writes down — rule 5 and the
Guardrails make commit default-closed, and "do not push" does not authorize commit.

`implementPostcondition` already computed everything needed for the twin case; it simply did not
say it. It now reports `uncommitted` — a delta exists and `HEAD` did not move — in both branches of
the report. This is the more dangerous half of the pair, because unlike the empty case it **looks**
like success.

A new `--deliver commit` flag, scoped to `implement`, injects the authorization through a template
placeholder rather than string concatenation; without the flag the prompt is byte-identical to
before. It also creates a checkable postcondition: ask for a commit, get no `HEAD` movement, and the
job ends in `attention` with `implement_uncommitted`. The default stays closed, and push and PR keep
requiring explicit authorization — those leave the machine, a commit does not.

Why the default was not simply flipped: the authorization sentence, applied by hand during that
run, **still failed twice afterwards**. Authorizing does not guarantee obedience. A verified
postcondition catches it either way.

## Runs spent waiting on background

Whole runs were consumed launching `pnpm test` in the background and waiting for it, with zero files
written. Rule 2 of the implement template already forbade delegating to a subagent and waiting on
it; it said nothing about shell commands — the same waste for the same reason. The hole is closed
inside the rule that already existed, rather than adding a new one.

## A probe that lies when cold

`workers` reported two workers as `unavailable` with version `-`, while their binaries were present
in `PATH` and answered `--version` normally. The cause was in the code: a 1500 ms timeout and a
single `catch` collapsing ENOENT, EACCES and timeout into one verdict. The profile wrappers start
Python and provision a keychain on first use; 1500 ms passes easily.

Status is now three-way:

- ENOENT/ENOTDIR/EACCES/EPERM → `unavailable`. Final, no retry: more time does not make a missing
  binary appear.
- A timeout earns one longer second attempt. If that also expires → `unknown`, which is *not*
  `unavailable`. It is excluded from `--worker auto` — never dispatch blind — but stays selectable
  by explicit id.

Worth recording, because the obvious implementation gets it wrong: an `execFile` timeout does **not**
arrive as `ETIMEDOUT`. It comes with `killed: true`, `signal: 'SIGTERM'` and `code: null`. Measured,
not assumed.

`AGY_PROBE_TIMEOUT_MS` and `AGY_PROBE_RETRY_TIMEOUT_MS` make both budgets configurable, in the same
spirit as `AGY_POOL_BINS`. An invalid value is ignored rather than obeyed: a stray zero would mark
every worker `unknown`, which is worse than the default it replaced.

## Quota slack in the pool

Avoiding a profile sitting at 97% of its window meant remembering it. The slack was already captured
on disk by an external hook; the pool just never looked.

`discoverWorkers` now returns `quotaSlack` and `quotaAgeMs`, read from the quota cache
(`AGY_QUOTA_CACHE_DIR` to relocate it; this process only ever reads). `--worker auto` breaks ties by
more slack, falling back to the older least-load rule whenever slack is unknown or tied — a stale or
missing cache never blocks the pool.

The `workers` table gains the column, **with the age of the reading beside it**. `93% (4h)` and
`93% (2d)` are not the same claim, and a percentage without its age is the kind of number that gets
trusted for days. No reading prints `-`, which is an answer, not a failure.

The same table stopped deriving its status text from the older `available` boolean, which was
collapsing `unknown` back into `unavailable` — the exact false negative the three-way probe exists
to remove.

## Documentation

- `skills/jobs` publishes the ten-section dispatch format that converged over that run, including the
  two sections that paid for themselves: asking the executor to report contradictions between the
  spec and the real code, and giving a numeric test baseline instead of accepting "the tests pass".
- `skills/pool` now warns that a fresh worktree does **not** inherit `.env`, because it is gitignored.
  Five suites failed with `POSTGRES_URL environment variable is not set` and looked like a
  regression. It was environment.
- `docs/agy-vs-codex.md` records when to dispatch which, and why.
