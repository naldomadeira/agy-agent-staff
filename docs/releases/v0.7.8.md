# v0.7.8

## The calling agent can now tell which model to reach for

Every persona already accepted `--model <id>` and `--effort`, each with its own default, and the
skills documented the flags. None of them said which ids exist or when overriding is worth it, so
the caller never escalated: a task the flash tier could not carry ran on the flash tier anyway.

`skills/jobs/references/model-routing.md` is the shared answer, pointed at from the five personas
that take a model. It deliberately does **not** list the ids — that list changes and a copy of it
goes stale in silence. It sends you to `agy models`, the same source `handleUnsupportedModel`
consults when a `--model` is rejected, explains how to read the ids, and gives the rules: flash for
volume, `gemini-3.1-pro` and the Claude ids for reasoning that has to be worked through, `--effort`
tried before switching families, and Anthropic quota spent when it resolves the task rather than by
habit.

## Subdelegation is now the dispatcher's call

An `implement` job ran for 4m33s and wrote nothing: agy delegated to a subagent of its own, waited
on it, and the outer job closed before that subagent produced anything.

`templates/implement.md` never mentioned delegation at all, and its "verify before you finish" was
loose enough that launching a subagent could pass for finishing. The new rule 2 inverts the default
without forbidding the tool: execute directly unless the task text explicitly asks for subagents,
and when it does, dispatching one and waiting on it is still not finishing — the changed files have
to exist on disk and have been inspected.

`templates/staffer.md` is untouched on purpose. It has no numbered rules by design — its skill
documents that the task defines its own output — and a staffer deliverable is not necessarily a file
on disk, so the finishing criterion does not transfer.
