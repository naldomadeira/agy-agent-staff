# agy-staff 0.7.6 — Fork identity and worker-pool correctness

## Changes since 0.7.5

This release finishes the `agy-agent-staff` fork rename that 0.7.4/0.7.5 left incomplete, and fixes a handful of worker-pool correctness issues found while auditing that rename.

### Fork identity

- Install and upgrade commands pointed at a plugin id that never resolved: the marketplace is named `agy-staff` while the repository is `agy-agent-staff`, so `agy@agy` failed silently. Every install/upgrade command now uses `agy@agy-staff` — the id after `@` is the marketplace name, not the repository name, and that does not change.
- The agent-facing "For agents" path (`docs/INSTALL_FOR_AGENTS.md`, linked from the README) pointed agents at the upstream `keli-wen/agy-staff` repository, so following it installed the wrong project. It now installs from `naldomadeira/agy-agent-staff` throughout, including the raw-URL instruction agents are told to `curl`, and its Pi skill checklist now includes `agy-pool`.
- `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`, and `package.json` now point `repository`/`homepage`/`bugs` at this fork instead of upstream, and list Naldo Madeira as maintainer alongside Keli Wen's original authorship, kept as `author`/`owner` for MIT attribution. The `agy-staff` marketplace name is unchanged by design — installs already made against `agy@agy-staff` must keep resolving. `package.json`'s own `name` moves from `agy-staff` to `agy-agent-staff` to stop colliding with the upstream package name; nothing in the companion, tests, or skills reads that field, so nothing else is affected.
- Docs and manifests described the plugin as "five personas" in several places. It exposes eight skills — staffer, researcher, reviewer, implementer, ask, lead, pool, and the model-only jobs skill — and every count is corrected, including in the Chinese reference.

### Worker-pool correctness

Auditing the optional worker pool (0.7.4) and its telemetry (0.7.5) surfaced four correctness gaps, now fixed:

- A race between selecting a worker and registering the job against it could let two dispatches land on the same worker past its capacity.
- Workers discovered through more than one path (for example a `PATH` hit and an explicit config entry pointing at the same binary) are now deduplicated by canonical path instead of being counted as separate workers.
- The preflight check meant to catch an unavailable worker before dispatch was unreachable in a code path that skipped it; it now runs on every dispatch that requests a specific worker.
- "Busy" (over capacity, but reachable) and "unavailable" (not reachable at all) were reported the same way; they are now distinguished so a caller can tell the two apart.

Worker identity now also appears in `wait`'s completion output and in job telemetry, extending the dispatch/list/observe/diagnostics coverage that 0.7.5 added.

**Without `--worker`, nothing changes for a single-worker installation.** All of the above only affects the opt-in pool path; the legacy `AGY_BIN || agy` resolution is untouched.

### Documentation

`docs/REFERENCE.md` and `docs/REFERENCE.zh-CN.md` had a heading bug: the "Optional worker pool" section was inserted between "Modes and defaults" and its own content, so the persona table and the `lead` paragraph rendered under the wrong heading. Both files are restructured so every heading owns its own content again, the persona table gains a `pool` row, and the flags table now documents `--worker <id>` (accepting `auto` as well). The Chinese reference and `README.zh-CN.md` also pick up the "every dispatch, status entry, and observation identifies its external AGY worker" sentence that 0.7.5 had only added to the English docs.

## Validation

- The offline suite passes: 216 tests (210 before, plus six covering pool reservation and affinity).
- `npm run check:pi` confirms the generated Pi skills stay in sync with the canonical `skills/` sources.

## Upgrading

Update the plugin and restart the host to load version `0.7.6`. Claude Code: `claude plugin marketplace update agy-staff && claude plugin update agy@agy-staff`. Codex: `codex plugin marketplace upgrade && codex plugin add agy@agy-staff`. See the [upgrade instructions](../REFERENCE.md#upgrading) for the force-refresh command if a fix does not show up after restarting.
