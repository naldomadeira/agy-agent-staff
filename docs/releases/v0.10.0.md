# v0.10.0

An implement run spends its time on the task, and the companion checks the result itself. In one
production run, the briefing told the worker to "run `pnpm check` and `pnpm build` to confirm the
state of the project". The worker spent the entire run on that and delivered zero files. The same
session that documented the problem fell into it again a few hours later. A written warning did not
prevent it, so the companion now enforces the rule itself.

## Pre-dispatch refusal

An `implement` briefing that orders a full gate is refused before anything runs: exit 1, no job and
no agy call. A full gate is a build, check, lint or typecheck, or a test command with no target
(`pnpm test`, `pytest`, `go test ./...`). The error quotes the offending line. A targeted test
(`pnpm test src/x.test.ts`, `pytest tests/x.py`, `-k`, `-t`, `--filter`, `::`) is allowed. So are
negations ("don't run `pnpm build`") and prose that describes a command rather than ordering it. The
check covers `--prompt`, `--prompt-file`, `--stdin`, `continue` and `restart`, including specs
written before this release. `--allow-gate` lets the worker run the gate anyway, and `restart`
keeps it.

## Decision discipline

The implement template has four new rules. A briefing fact that the code contradicts means stop and
report it with file:line evidence. A project rule wins over a fallback the worker invents. A new code
path must name who reaches it in production. The worker gets its time budget and runs no unauthorized
full gate. The spec now records the original task, the rendered prompt and `policy_version`.

## Declared gates

```json
{ "gates": { "check": "pnpm check", "build": "pnpm build" } }
```

- Put the gates in `.agy-staff/config.json`. The companion reads the workspace's file first, then
  the main worktree's, so pool worktrees work too.
- `--gate check,build` runs them in order and stops at the first failure. `--gate-cmd "<cmd>"`
  runs one ad hoc command. `--gate-timeout` defaults to 15m and does not count against the agent's
  `--timeout`.
- Gates run after the agent finishes. The job is in phase `verifying` meanwhile, and `status`,
  `observe` and `wait --follow` show it. Each gate runs in its own process group. A gate timeout or
  a cancel kills the whole process tree.
- The report gets a `## Companion verification` section. A failure or timeout ends the job
  `attention` with reason `gate_failed` (exit 5) and keeps the response and the diff. Gates that pass
  turn the worker's own `verification_incomplete` into `done`. Gates never run after quota, error,
  timeout, cancel, `implement_no_changes` or `implement_uncommitted`.
- `continue` and `restart` reuse the job's gates unless new ones are passed. An unknown gate name is
  refused before dispatch.
