# v0.7.7

## An implement run that changes nothing now asks for attention

A real `implement` job ran for 4m33s, wrote no files, and reported `done` with exit 0. agy had
delegated to a subagent of its own and the outer job closed before that subagent produced
anything. The only way to find out was to inspect the working tree by hand.

The companion already had the evidence. `porcelainDelta` snapshots `git status --porcelain`
before and after every non-`ask` run and prints the difference in the report — in that job it
printed `(none detected by porcelain status)` and then reported success anyway. The delta was
computed, printed, and ignored.

`implement` exists to edit the working tree. A run that ends without having changed anything
did not deliver, and now says so: `status: attention`, exit code 5, with a message naming what
happened and what to do about it. Both already existed; only timeouts with a resumable
conversation used them until now.

**Delivery by commit still counts as work.** Rule 4 of the implement template lets agy commit,
push or open a PR when the task asks for it, which leaves the working tree clean and the
porcelain delta empty. Flagging that would be a worse false positive than the original bug, so
the condition is an unchanged tree **and** an unmoved `HEAD`. A repository with no commits yet
is distinguished from no repository at all, and when git is unavailable the previous behaviour
is kept rather than a verdict invented.

Only `implement` is affected. `research`, `review` and `ask` read by design, so an empty delta
is their normal result; `staffer` is general enough that not writing can be correct. The text of
the existing tree report is unchanged, word for word.
