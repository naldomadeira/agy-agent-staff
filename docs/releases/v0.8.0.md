# v0.8.0

## Every flag is now scoped to the subcommands that read it

0.7.9 fixed one case: `--worker` was accepted and ignored on the subcommands that never look at
it. The underlying problem stayed — `parseFlags` is global and does not filter by subcommand, so
`status --model x`, `cancel --timeout 5m` and `workers --stdin` were all accepted in silence.

Measured before this change: of 224 (subcommand, flag) pairs, **217 were accepted** and only the
seven `--worker` refusals from 0.7.9 were not. Afterwards, 141 are refused.

`FLAG_SCOPE` replaces the `--worker` special case with a map of which flags each subcommand
actually reads, checked once in `main()` before dispatch. The map was derived by reading each
handler and following the indirect calls — `resolveRun`, `planWorker`, `loadProjectConfig` — not
from the flag names.

```
agy-staff error: --model has no effect on status: it selects the agy model for a run
(valid on: staffer, research, review, implement, ask, continue)
```

Exit code 1, the same as every other argument error.

## What that surfaced

- `--json` was read for every mode but only ever acted on `review`. It is now accepted there and
  refused elsewhere, instead of being quietly dropped.
- `restart` discarded `--model`, `--effort`, `--restricted`, `--conversation` and `--job`: it
  replays the stored job spec, not the new invocation. Those are refused now.
- `--continue` is a no-op on the `continue` subcommand itself, which always resolves a
  conversation id first.
- `--dry-run` is never read anywhere in the codebase. It stays accepted on `setup` alone, where
  a test documents it as an intentional no-op alias and setup already dry-runs without `--apply`.

`restart` still accepts `--prompt`, `--prompt-file` and `--stdin` and ignores them. That is not an
oversight: an existing test invokes `restart <id> --prompt "ignored"` and expects it to succeed.
The behaviour is now documented and covered by a regression test proving the restarted job replays
the original task rather than the passed-in one.

## Compatibility

A flag that was silently dropped now fails loudly. Any invocation that relied on passing an
irrelevant flag will need it removed. Nothing that was documented changes: every flag advertised in
a skill's `argument-hint`, in the body of the `jobs` skill, or in `docs/REFERENCE.md` is still
accepted by the subcommand that advertises it — verified pair by pair.

## Validation

- `npm test`: 265 passing, 0 failing, 32 suites (228/31 before).
- The 29 new rejection cases were run against the previous `companion/agy-companion.mjs` and all 29
  fail there.
- `npm run check:pi`: 13 files, 0 changed.
- The full 224-pair acceptance matrix was generated by invoking the CLI for every pair, before and
  after, and cross-checked against every flag the skills and reference docs advertise. No
  documented invocation is refused.
