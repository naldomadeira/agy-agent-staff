# v0.8.4

`unknown` was excluded from `--worker auto`. That looked prudent and was not.

The state exists because of a false negative: a probe with a 1500 ms budget and a single `catch`
reported two perfectly good profiles as `unavailable`, and that capacity sat unused while someone
went hunting an installation problem that did not exist. Refusing those same workers in `auto`
repeats the waste by another route — it turns "not there" into "there, but not counted on".

`unknown` is now eligible for `auto`, ranked behind everything that answered the probe. It is used
when nothing better is free, never instead of a worker that answered. Within each group the quota
slack still decides, and load still breaks the tie.

A dispatch to a worker that turns out to be dead fails fast and says so. Idle capacity never fails,
which is exactly why nobody sees it.

`unavailable` is unchanged and still final: a binary that is not there, or not executable, is not
capacity, and more patience does not make it one.

## Verification

`npm test`: 36 suites, 310 tests, 310 pass, 0 fail. Three new tests cover the change: `auto` reaches
for an `unknown` once the available worker is busy, still refuses an `unavailable` in the same
situation, and quota slack still orders two `unknown` workers between themselves.
